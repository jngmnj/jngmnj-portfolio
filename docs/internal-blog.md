# 내부 블로그 비활성화 / 재개

내부 블로그는 삭제하지 않고 `src/constants/features.ts`의
`INTERNAL_BLOG_ENABLED = false`로 비활성화한다. Firebase 데이터는 변경하지
않는다.

- `/blog`와 `/ko/blog`, `/en/blog` 및 하위 주소는 외부 블로그로 임시
  이동(307)한다.
- 기존 글 작성 API는 데이터 저장 전에 503을 반환한다.
- 공통 OG API는 내부 게시글 데이터를 조회하지 않는다.
- 블로그 화면, 작성 기능, 전용 컴포넌트와 번역은 보존한다.
- 헤더와 사이드바의 블로그 메뉴는 기존 외부 블로그 링크를 유지한다.

## 다시 열기

1. 기존 작성 기능의 인증·권한 및 Firebase 보안 규칙을 재검토한다.
2. `INTERNAL_BLOG_ENABLED`를 `true`로 바꾼다.
3. 필요하면 헤더와 사이드바의 블로그 메뉴를 현재 언어의 내부 `/blog` 주소로
   변경한다.
4. 타입 검사, ESLint, 빌드를 실행하고 게시글 조회·작성·오류 처리를 확인한다.
5. 개발 서버를 재시작하거나 새 빌드를 배포한다. 리다이렉트 설정은 빌드/서버 시작
   시 반영된다.

임시 리다이렉트를 사용하므로 이번 비활성화가 영구 이동으로 캐시되지 않는다. 공개
사이트의 재개 및 배포는 별도 승인 후 진행한다.
