# 공통 컴포넌트 사용 가이드

**Components**에는 실제 앱 컴포넌트가, **Foundations**에는 앱 스타일과 토큰이
있습니다. **Example**은 Storybook의 참고 예제입니다.

## 먼저 확인할 것

1. **Controls**로 props를 바꾸고 **Actions**에서 이벤트를 확인합니다.
2. **Viewport**에서 모바일·태블릿·데스크톱을 전환합니다.
3. **Interactions**에서 클릭·입력·폼 제출·키보드 테스트를 확인합니다.
4. **Accessibility**에서 대비와 레이블 등 개선 항목을 확인합니다. 현재 검사는
   `todo` 모드입니다.

## 디자인 원칙

둥근 표면과 충분한 여백, 조용한 테두리, 읽기 쉬운 제목과 보조 문구를 사용합니다.
강조색은 한 번에 하나를 사용하고 그림자는 최소화합니다. 색상·간격을 추가하기
전에 Tokens에서 기존 값을 먼저 확인하세요.

## 컴포넌트 선택

| 목적           | 컴포넌트  | 사용 시 확인                                                 |
| -------------- | --------- | ------------------------------------------------------------ |
| 동작 실행·이동 | Button    | href가 있으면 Link. 링크 모드는 disabled/onClick 전달 미지원 |
| 기본 입력      | Input     | 외부 label 또는 aria-label 필요                              |
| 폼 검증        | FormInput | register와 errors 연결, 기본 필수 입력                       |
| 동의·선택      | CheckBox  | children 레이블, Space 키, disabled 확인                     |
| 작업 결과 안내 | Toast     | onClose에서 제거, 기본 3초 후 종료                           |

```tsx
import Button from '@/components/common/Button';
import Input from '@/components/common/Input';

<label htmlFor="contact-email">이메일</label>
<Input id="contact-email" name="email" type="email" />
<Button type="submit" color="primary" size="medium">저장하기</Button>
```

## 한글·영어와 접근성

긴 문구는 LongLabel/LongMessage 스토리에서 확인합니다. 입력창의 placeholder를
레이블 대신 사용하지 마세요. 키보드 포커스, 비활성화 상태, 상태 알림과 오류
안내를 함께 검토합니다. 접근성 검사 결과가 표시되어도 `todo` 모드에서는 테스트를
실패시키지 않으므로 별도로 확인해야 합니다.

자세한 실행·테스트 방법, 구현 제한과 후속 작업은 저장소의
`docs/design/storybook.md`에 정리되어 있습니다.
